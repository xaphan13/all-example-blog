# Руководство для агентов

Этот файл помогает AI-агентам эффективно работать с проектом `diegolonio.com`.

## Сначала: читайте документацию

Перед внесением изменений или ответами на вопросы о кодовой базе всегда читайте пронумерованные файлы документации в папке `docs/`:

1. [`docs/01_project_structure.md`](./docs/01_project_structure.md) — назначение проекта, дерево директорий, ключевые файлы и внешние зависимости.
2. [`docs/02_architecture.md`](./docs/02_architecture.md) — высокоуровневая архитектура, слои и паттерны.
3. [`docs/03_execution_flow.md`](./docs/03_execution_flow.md) — жизненный цикл приложения и ключевые бизнес-процессы.
4. [`docs/04_code_quality.md`](./docs/04_code_quality.md) — оценка качества кода и технический долг.
5. [`docs/05_optimization_roadmap.md`](./docs/05_optimization_roadmap.md) — дорожная карта и предложения по улучшению.

Эти файлы являются единственным источником правды по структуре проекта и замыслу архитектуры. Избегайте лишнего обхода всего проекта; сначала обращайтесь к документации в `docs/`.

## Как подходить к задачам

- Делайте минимальные и сфокусированные изменения.
- Следуйте существующему стилю Python: type hints, чистый SQL в `app/queries/`, внедрение зависимостей через `Depends(get_db)`.
- Отдавайте предпочтение серверному рендерингу Jinja2; не вводите frontend-фреймворки и тяжёлый JavaScript.
- Сохраняйте философию «без ORM, без CMS», если явно не попросят иначе.
- Добавляйте новые SQL-миграции в `migrations/` с последовательными именами с нулевым паддингом (например, `002_add_index.sql`).
- Запускайте миграции и проверяйте запуск приложения после любых изменений БД.
- Если добавляете новую зависимость, обновите `pyproject.toml` и перегенерируйте `uv.lock`.

## Ключевые точки входа

- `app/main.py` — точка входа FastAPI, lifespan, монтирование статики, роутеры.
- `app/config.py` — конфигурация окружения.
- `app/database.py` — пул соединений PostgreSQL.
- `app/routers/public.py` — публичные маршруты.
- `app/routers/admin.py` — маршруты админ-панели.
- `app/queries/` — SQL-запросы.
- `app/templates/` — шаблоны Jinja2.
- `migrations/` — SQL-миграции схемы.

## Проверка изменений

1. Запустите базу данных: `docker-compose up -d`
2. Примените миграции: `python migrations/run_migrations.py`
3. Запустите приложение: `uv run uvicorn app.main:app --reload`
4. Проверьте соответствующие страницы и endpoints админки.

## Примечания по языкам

- Комментарии в исходном коде могут быть на испанском. Для новых комментариев отдавайте предпочтение английскому.
- Пользовательские шаблоны могут быть на испанском; сохраняйте существующий язык, если не попросят локализовать.
