# AmiaBlog — Руководство для агентов

## Обзор проекта

AmiaBlog — это простая и лёгкая блог-система, построенная на **FastAPI** и **MDUIv2**. Это проект на Python 3.11+, управляемый с помощью **UV**. Контент пишется в Markdown с YAML frontmatter. Посты хранятся в виде обычных файлов, рендерятся на стороне сервера через шаблоны Jinja2 и отдаются FastAPI. Проект также поддерживает опциональную генерацию статического сайта и встроенную i18n.

Этот репозиторий предназначен для AI-агентов кодирования. В нём пока нет тестового набора; корректность обеспечивается форматированием кода (Black), проверкой типов (Pyright) и runtime-валидацией (Pydantic).

## Технологический стек

- **Язык / Runtime:** Python >=3.11
- **Менеджер пакетов:** [UV](https://github.com/astral-sh/uv) — использует `pyproject.toml` и `uv.lock`
- **Веб-фреймворк:** FastAPI, запускается через Uvicorn
- **Шаблонизация:** Jinja2 с кэшированием шаблонов и минификацией HTML (`htmlmin`)
- **Валидация / Модели:** Pydantic v2
- **Markdown:** Рендерится на клиенте с помощью `markdown-it` (в `static/`); сервер хранит только сырой Markdown
- **UI / CSS:** MDUI v2.1.4, шрифт Roboto, Material Icons
- **Поиск:** Полнотекстовый поиск SQLite в памяти; опциональная токенизация `jieba-fast` для нечёткого поиска на китайском/английском
- **Горячая перезагрузка:** Watchdog отслеживает `data/posts/*.md` и автоматически перезагружает посты в памяти
- **Live Preview:** Опциональное live-preview на базе WebSocket только для разработки
- **Подсветка синтаксиса:** Highlight.js 11.1.1; языковые пакеты загружаются по требованию через `httpx`
- **Логирование:** loguru

## Конфигурация

Вся runtime-конфигурация находится в `config.json`. Pydantic валидирует её при запуске; некорректная конфигурация не даст приложению стартовать.

Важные ключи:

- `site_settings` — title, description, keywords, `site_url`, `color_scheme` (HEX), `theme` (`auto`/`light`/`dark`), `hljs_languages`.
- `site_language` — например, `en` или `zh-CN`. Соответствует `languages/{lang}.json`.
- `search_method` — `fullmatch` (быстрый, почти точный) или `jieba` (по токенам, лучше для китайского).
- `copyright` — опциональная информация о лицензии в подвале.
- `friend_links` — опциональный список ссылок.
- `cloudflare_analytics_token` — опциональный токен аналитики.
- `disable_template_cache` — устанавливайте в `true` только при разработке шаблонов.
- `live_preview` — установите в `true`, чтобы включить экспериментальный WebSocket live-preview. **Только для разработки.**

Полный справочник см. в `docs/configuration.md`.

## Команды сборки и запуска

Установка зависимостей (всегда запускайте первым делом в свежем клоне):

```bash
uv sync
```

Запуск development-сервера:

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

Развёртывание в стиле продакшена с Gunicorn + Uvicorn-воркеры:

```bash
uv run gunicorn main:app -w 4 -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8000
```

Генерация статического сайта:

```bash
uv run staticify.py --destination dist/ --remove-existing
```

## Стиль кода и линтинг

- **Форматтер:** Black, целевая версия Python 3.11. Конфигурация неявно задаётся в `.pre-commit-config.yaml` и CI.
- **Проверка типов:** Pyright.
- **Pre-commit:** `.pre-commit-config.yaml` запускает `uv run black . --check --target-version py311` и `uv run pyright`.
- **CI:** `.github/workflows/black-check.yml` и `.github/workflows/pyright-check.yml` запускаются при каждом push и pull request.

Проверка локально перед коммитом:

```bash
uv run black --check .
uv run pyright
```

Автоформатирование:

```bash
uv run black .
```

## Тестирование

В этом репозитории пока нет тестового набора. Проверяйте изменения следующим образом:

1. Запустите `uv run black --check .` и `uv run pyright`.
2. Запустите сервер и посетите маршруты (`/`, `/posts`, `/search`, `/post/{slug}`, `/feed`, `/sitemap.xml`).
3. Для статической генерации запустите `uv run staticify.py --destination dist/ --remove-existing` и проверьте вывод.

## Конвенции разработки

- **Сообщения коммитов:** следуйте [Conventional Commits](https://www.conventionalcommits.org/).
- **Интернационализация:** При добавлении переводов используйте плейсхолдеры в стиле `str.format` / Jinja2, если в термине 2+ плейсхолдера, потому что порядок слов различается между языками. Ключи переводов живут в `languages/*.json` и доступны в шаблонах через `i18n.<key>`.
- **Шаблоны:** Используйте предоставленный фильтр Jinja2 `urlencode` для небезопасных для URL имён тегов. Проверяйте `is_static`, чтобы переключаться между динамическими путями (`/feed`) и статическими (`/feed.xml`) при генерации статического вывода.
- **Посты:** Markdown-файлы с YAML frontmatter кладутся в `data/posts/`. Устаревший формат метаданных без разделителей `---` всё ещё парсится, но считается устаревшим. Слаги постов берутся из имён файлов (например, `my-post.md` → slug `my-post`).
- **Вложения:** Помещайте файлы в `data/attachments/` и ссылайтесь на них как `/attachments/<filename>`.
- **Подсветка синтаксиса:** Добавляйте названия языков в `config.json` в раздел `site_settings.hljs_languages`. Недостающие пакеты загружаются автоматически в `static/hljs_11.1.1/`.

## Архитектура runtime

- `main.py` создаёт единое приложение FastAPI с асинхронным lifespan.
- При запуске `load_config()` читает `config.json`, `PostsManager` загружает все опубликованные посты из `data/posts/`, и запускается watchdog-наблюдатель.
- `PostsManager` хранит посты, теги и индекс поиска SQLite в памяти. Поддерживает горячую перезагрузку при изменении файлов (с задержкой 0.5 с).
- Маршруты возвращают `HTMLResponse`, отрендеренный `TemplateRenderer`, который минифицирует вывод с помощью `htmlmin`.
- `/static` и `/attachments` монтируются через `StaticFiles`.
- WebSocket live-preview (`/api/live-preview-ws`) включается только когда `config.live_preview` равен `true`. Он отправляет обновления контента подключённым браузерам при редактировании поста.
- Генерация статического сайта переиспользует тот же стек рендеринга, но отключает поиск и пишет файлы в целевую директорию.

## Вопросы безопасности

- **Live preview — экспериментальный и по умолчанию отключён.** Не включайте его в продакшене; в комментариях кода предупреждается о возможных проблемах с производительностью и безопасностью.
- В системе нет слоя аутентификации или авторизации. Любой пользователь с сетевым доступом может читать опубликованные посты, запускать поиск и получать доступ к RSS/карте сайта.
- `config.json` может содержать `cloudflare_analytics_token`; не коммитьте настоящие секреты в систему контроля версий, если только репозиторий не является приватным и предназначенным для этого.
- Метаданные постов валидируются Pydantic, но Markdown-контент постов рендерится на клиенте с помощью `markdown-it` в браузере. Сервер не санитизирует HTML, произведённый клиентским рендерером.
- `get_commit_hash` использует `os.popen("git rev-parse HEAD")`, что полагается на shell-выполнение при запуске. Это только для чтения, но не должно быть доступно недоверенному вводу.
- `staticify.py` будет запрашивать подтверждение пользователя перед перезаписью существующей целевой директории, если не передан `--remove-existing`. В автоматических скриптах предпочитайте `--remove-existing`, чтобы избежать интерактивных зависаний.

## Варианты развёртывания

1. **Динамический сервер:** Запустите `uv run uvicorn` или Gunicorn за обратным прокси (Nginx, Caddy и т.п.).
2. **Статический сайт:** Запустите `staticify.py` и раздавайте сгенерированную директорию с любого статического хостинга. В README упоминается шаблон для GitHub Pages + GitHub Actions по адресу `0x24a/AmiaBlog-GitHub-Pages-Template`.
3. **Docker / контейнер:** В этом репозитории не предоставляется; вам нужно будет собрать небольшой образ, который устанавливает UV, копирует проект и запускает команду Uvicorn.

## Типичные задачи

### Добавить новый язык

1. Скопируйте `languages/en.json` в `languages/<code>.json`.
2. Переведите значения, сохраняя плейсхолдеры `{}` или `{name}` нетронутыми.
3. Установите `site_language` в `<code>` в `config.json`.

### Добавить новую страницу или маршрут

1. Добавьте маршрут в `main.py`.
2. Создайте шаблон в `templates/`, расширяющий `base.html`, если нужен общий макет.
3. Если страница должна появиться в статической навигационной панели, также обновите `templates/base.html`.
4. Если страница должна генерироваться статически, добавьте соответствующую логику рендеринга в `staticify.py`.

### Изменить цвет темы

Установите `site_settings.color_scheme` в `config.json` в HEX-значение (с `#` или без). MDUI автоматически сгенерирует палитру в браузере.

### Изменить поведение поиска

Измените `search_method` в `config.json` на `fullmatch` или `jieba`. Реализация поиска находится в `core/posts.py` в `PostsManager.search()` и `_build_search_index()`.

## Устранение неполадок

- `Error: the default posts directory has been changed to data/attachments`: это означает, что у вас всё ещё есть старая директория `attachments/` в корне репозитория. Переместите её в `data/attachments/`.
- `site_url` не задан: приложение будет использовать `https://example.com/` в качестве запасного варианта и выведет предупреждение. Ссылки в RSS-ленте будут неверными.
- Посты не отображаются: проверьте, что `published: true` установлено в frontmatter и что файлы находятся в `data/posts/` с расширением `.md`.
- Watchdog перезагружает слишком часто: задержка уже установлена в 0.5 секунды. Группируйте крупные правки файлов или временно останавливайте сервер.
