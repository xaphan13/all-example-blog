# Оценка качества кодовой базы

## Общая оценка

Кодовая база — **небольшой, хорошо структурированный демо-проект**. Архитектурные решения (фабрика приложения, агрегация роутеров, централизованная конфигурация, слой `core/`) соответствуют лучшим практикам FastAPI. Читаемость высокая, модульность соблюдена, связность низкая в пределах заявленного объёма.

**Ограничение**: проект намеренно минимален, поэтому многие аспекты production-ready системы (тесты, логирование, обработка ошибок, БД, аутентификация) отсутствуют. Ниже оценка именно в контексте демо и пути роста до production.

---

## Соответствие стандартам

### SOLID

| Принцип | Оценка | Пояснение |
|---|---|---|
| **S**ingle Responsibility | ✅ | Роутеры отвечают за HTTP, `core/config.py` — за конфиг, `core/templating.py` — за шаблоны. |
| **O**pen/Closed | ⚠️ | Расширение через добавление роутеров работает, но бизнес-логика встроена в обработчики; рост приведёт к нарушению. |
| **L**iskov Substitution | N/A | Нет иерархий классов. |
| **I**nterface Segregation | ✅ | HTML и API разнесены по разным роутерам. |
| **D**ependency Inversion | ⚠️ | Роутеры напрямую импортируют `templates` и `settings`; нет явного DI-контейнера, хотя для демо это допустимо. |

### DRY

- ✅ Шаблоны наследуют `base.html`, используют partials.
- ✅ Конфигурация в одном месте.
- ✅ Роутеры не дублируют настройку Jinja2.
- ⚠️ Повторяется паттерн `templates.TemplateResponse(request, "pages/...html", {...})` в каждом обработчике — допустимо при двух страницах, но при росте стоит вынести вспомогательный рендерер.

### KISS

- ✅ Проект максимально простой, без избыточных абстракций.
- ✅ Нет over-engineering для демо-задачи.

### Идиомы Python / FastAPI

- ✅ Используется современная сигнатура `TemplateResponse(request, "...", {...})`.
- ✅ Асинхронные обработчики (`async def`).
- ✅ `pydantic-settings` для конфигурации.
- ✅ `pathlib.Path` вместо строковых путей.
- ✅ `__name__ == "__main__"` guard для запуска.

## Технический долг и code smells

### 1. Отсутствие тестов

- Нет unit-, integration- и end-to-end тестов.
- Нет тестового клиента FastAPI (`TestClient`).
- **Риск**: регрессии при изменении роутеров или шаблонов не отлавливаются автоматически.

### 2. Бизнес-логика внутри обработчиков

- `routers/pages.py::index` содержит список `features` прямо в теле функции.
- При добавлении новых страниц/данных роутеры разрастутся.
- **Рекомендация**: вынести данные и бизнес-логику в слой `services/`.

### 3. Отсутствие обработчиков исключений и централизованного логирования

- Нет `@app.exception_handler`.
- Нет `logging` конфигурации.
- Нет структурированных логов.
- **Риск**: в production сложно диагностировать ошибки.

### 4. Нет CORS-конфигурации

- Если фронтенд будет на другом домене/порту, запросы к `/api/ping` будут заблокированы.
- **Рекомендация**: добавить `CORSMiddleware` с параметрами из `settings`.

### 5. Статика без cache-control

- `StaticFiles` используется без настройки заголовков кэширования.
- **Риск**: лишняя нагрузка на сервер и медленная загрузка страниц.

### 6. Tailwind через CDN

- Внешний CDN блокирует автономную работу без интернета.
- Нет очистки неиспользуемых классов, больший размер CSS.
- Для production рекомендуется локальная сборка через Tailwind CLI / PostCSS.

### 7. Docker Compose: внешняя сеть и отсутствие healthcheck

- `compose.yaml` зависит от заранее созданной сети `internal`.
- Нет `healthcheck` для сервиса `app`.
- Нет ограничений ресурсов (`deploy.resources`).

### 8. Нет типизации возвращаемых значений роутеров

- Обработчики не указывают `response_model` или возвращаемый тип.
- Пример: `async def ping()` вместо `async def ping() -> dict[str, str]`.
- **Риск**: слабая поддержка статического анализа, ухудшение документации OpenAPI.

### 9. Нет явного управления lifespan / startup / shutdown

- Нет событий `@app.on_event("startup")` / `@app.on_event("shutdown")` и modern `lifespan` контекстного менеджера.
- Для текущего масштаба не критично, но при добавлении БД/кэша станет обязательным.

### 10. Hardcoded строки в шаблонах

- Некоторые тексты (например, подвал, заголовки) зашиты в шаблонах.
- Для демо это нормально; для мультиязычности потребуется i18n.

## Оценка безопасности

| Аспект | Статус | Комментарий |
|---|---|---|
| Хранение секретов | ⚠️ | `.env` исключён из Git и Docker, но в коде нет чувствительных данных. |
| Валидация входных данных | N/A | Нет входных параметров у эндпоинтов. |
| Защита от инъекций | N/A | Нет БД, шаблоны рендерят только доверенные данные. |
| CORS | ❌ | Не настроен. |
| CSP / security headers | ❌ | Нет заголовков безопасности. |
| HTTPS / TLS | ❌ | Не настроен (ожидается на уровне reverse proxy). |
| Rate limiting | ❌ | Нет ограничения частоты запросов. |
| Зависимости | ⚠️ | Зависимости зафиксированы точными версиями, что хорошо, но нет аудита уязвимостей. |

## Оценка надёжности

- ✅ Приложение stateless, нет состояния, теряемого при перезапуске.
- ✅ Контейнеризация через Docker.
- ⚠️ Нет graceful shutdown (не критично без внешних соединений).
- ⚠️ Нет мониторинга и метрик.
- ❌ Нет healthcheck-эндпоинта.
- ❌ Нет retry/timeout-логики для внешних вызовов (сейчас внешних вызовов нет).

## Узкие места (bottlenecks)

1. **Синхронный рендеринг Jinja2 внутри async-обработчиков**. Хотя рендеринг быстрый, при очень больших шаблонах/высокой нагрузке он может блокировать event loop. Решение: `run_in_threadpool` для тяжёлых шаблонов.
2. **Отсутствие кэширования статики**. Каждый запрос к `/static/...` читает файловую систему.
3. **Отсутствие CDN для статики в production**. Все запросы идут на Uvicorn.
4. **Один рабочий процесс**. `uvicorn.run("main:app", ...)` без `--workers` и без Gunicorn запускает один процесс. Для production требуется несколько воркеров.
