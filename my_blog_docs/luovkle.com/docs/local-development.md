## Требования

Для работы необходимо установить следующие инструменты:

1.  **Python 3.13+** — основной язык проекта.
2.  **uv** — менеджер пакетов для Python (быстрая замена pip/poetry).
    *   Установка: `curl -LsSf https://astral.sh/uv/install.sh | sh`
3.  **pnpm** — менеджер пакетов для Node.js.
    *   Установка: `npm install -g pnpm` или через brew.
4.  **Git** — необходим для установки pre-commit хуков.

---

## Быстрый старт

Чтобы запустить проект локально, выполните две команды:

```bash
# 1. Установить все зависимости (Python, Node.js, Git hooks)
make setup

# 2. Запустить сервер разработки (FastAPI)
make local-dev
```

После этого сервер будет доступен по адресу: `http://localhost:4000` (порт можно изменить, см. ниже).

## Подробный разбор Makefile

### Переменные и Stamp-файлы

В начале файла объявляются переменные иStamp-файлы (файлы-маркеры). Они нужны для оптимизации: `make` проверяет время изменения файлов и пересчитывает зависимости только при необходимости.

*   `PORT ?= 4000` — порт сервера (можно переопределить: `make local-dev PORT=8000`).
*   `DEPS_STAMP` — маркер установки Python-пакетов.
*   `NODE_STAMP` — маркер установки Node-пакетов.
*   `STYLES_CSS` / `HIGHLIGHT_CSS` — пути к сгенерированным CSS-файлам.

### Цель: `setup` (Установка окружения)

```makefile
.PHONY: setup
setup: $(DEPS_STAMP) $(NODE_STAMP) $(PRECOMMIT_STAMP)
    @echo ">> Dev environment ready."
```

Выполняет три независимые задачи в одном вызове:

1.  **Python (`$(DEPS_STAMP)`)**:
    *   Запускает `uv sync --all-groups`. Устанавливает зависимости из `pyproject.toml` и `uv.lock` в виртуальное окружение `.venv`.
    *   Группы: `main` (runtime), `build` (pillow), `dev` (ruff, djlint, ty).
2.  **Node.js (`$(NODE_STAMP)`)**:
    *   Запускает `pnpm install --frozen-lockfile`. Устанавливает Tailwind CSS и CLI для сборки стилей.
3.  **Git Hooks (`$(PRECOMMIT_STAMP)`)**:
    *   Запускает `uvx prek install`. Устанавливает pre-commit хуки в `.git/hooks/`.
    *   Хуки включают: проверку типов (`ty`), линтинг и форматирование (`ruff`), проверку шаблонов (`djlint`).

### Цели: `local-dev` и `local-prod` (Запуск сервера)

#### `make local-dev`
Запускает сервер в режиме разработки с горячей перезагрузкой (hot-reload).
*   **Зависимости**: Сначала автоматически выполнит генерацию всех ассетов (CSS, изображения).
*   **Команда**: `fastapi dev --port 4000 app/main.py`

#### `make local-prod`
Запускает сервер в продакшн-режиме (без горячей перезагрузки, оптимизированный).
*   **Команда**: `fastapi run --port 4000 app/main.py`

### Генерация ассетов (CSS и Изображения)

Перед запуском сервера (`local-dev/prod`) Makefile гарантирует наличие сгенерированных файлов:

1.  **Tailwind CSS (`STYLES_CSS`)**:
    *   Собирается из `app/assets/input.css` в `app/static/css/styles.css`.
    *   В dev-режиме (`make local-styles`) запускается watcher, который следит за изменениями в CSS.
2.  **Подсветка кода (`HIGHLIGHT_CSS`)**:
    *   Генерируется утилитой `pygmentize` из темы `github-dark` в `app/static/css/highlight.css`.
3.  **Оптимизация изображений (`images-optimize`)**:
    *   Скрипт `cli.convert_images` конвертирует исходные PNG/JPG в более современные форматы (WebP/AVIF).
4.  **ANSI-изображения (`images-ansi`)**:
    *   Скрипт `cli.img_to_ansi` создает текстовые ASCII-арт версии изображений.

### Код-кwalити (Форматирование и Линтинг)

*   **`make format`** — применяет форматтеры (Ruff для Python, djlint для шаблонов, ruff-format).
*   **`make lint`** — запускает линтеры (`ruff check`, `djlint --lint`).
*   **`make check`** — комплексная проверка: запускает `prek run --all-files` (все pre-commit хуки на всех файлах проекта).

### Очистка проекта

*   **`make clean`** — удаляет сгенерированные статические файлы (CSS, webp, avif), кэш (`__pycache__`, `.cache`) и папки `ansi`/`author`.
*   **`make fclean`** — полная очистка (включает `clean` + удаляет `.venv`, `node_modules` и локальные кэши линтеров).
*   **`make re`** — "Reset": полная очистка + запуск stage-окружения через Docker (комбинация `fclean` и `stage`).

## Механика работы маркеров (Stamps)

В Makefile используется продвинутый паттерн **файлов-маркеров (stamps)** для управления зависимостями.

### Как это работает?

Вместо того чтобы запускать тяжелые команды (типа `uv sync`) каждый раз, мы создаем пустой файл-маркер (например, `.venv/.deps-installed`) после успешного выполнения команды.

```makefile
$(DEPS_STAMP): pyproject.toml uv.lock
    uv sync --all-groups
    @touch $@
```

1.  **Первый запуск**: Файл маркера не существует. `make` видит зависимость от `pyproject.toml`, запускает `uv sync`, создает маркер.
2.  **Повторный запуск (без изменений)**: `make` смотрит на время создания маркера и время изменения файлов `pyproject.toml` и `uv.lock`. Если маркер новее — правило **пропускается**.
3.  **При изменении зависимостей**: Вы поправили `pyproject.toml`. Его timestamp стал новее маркера. `make` решит, что правило устарело, и запустит `uv sync` заново.

### Символ `@` в командах
Пример: `@touch $@`.
Символ `@` в Makefile запрещает выводить саму команду в терминал, показывая только результат или echo. Это делает вывод `make` чище.

### Переменная `$@`
Это встроенная переменная Makefile, которая означает **"имя текущей цели"**.
Если цель — `$(DEPS_STAMP)`, то `@touch $@` превращается в `@touch .venv/.deps-installed`.
