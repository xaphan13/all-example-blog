# AGENTS.md — Сводное руководство для AI-агентов по воркспейсу `my_blog_docs`

> Этот файл — точка входа для AI-ассистентов (Koda, Copilot, Claude и др.), работающих
> с данным воркспейсом. Здесь описано, **что** находится в воркспейсе, **где** искать
> информацию по каждому проекту и **как** отвечать на вопросы по нескольким проектам сразу.

---

## 1. Что это за воркспейс

`my_blog_docs` — это **репозиторий документации**, а не исходного кода. Он содержит
**6 папок**, каждая из которых — документация для отдельного проекта. Внутри каждой папки:

- `AGENTS.md` (или `AGENTS.ru.md`) — правила работы агента с конкретным проектом;
- `README.md` (или `README.ru.md`) — описание проекта для людей;
- `docs/` — подробная документация (структура, архитектура, поток выполнения,
  качество кода, план оптимизации и т.д.).

**Исходного кода в этом воркспейсе нет.** Все вопросы отвечаются на основе
документации. Если информации не хватает — сообщи об этом, не выдумывай детали кода.

## 3. Общая структура документации внутри каждого проекта

Почти во всех проектах `docs/` пронумерована единообразно:

| Файл | Содержание |
|---|---|
| `01_project_structure.md` | Карта проекта: дерево директорий, роль каждого файла, зависимости |
| `02_architecture.md` | Архитектура, слои, паттерны, поток данных, конфигурация |
| `03_execution_flow.md` | Жизненный цикл приложения, бизнес-процессы, таблица роутов, middleware |
| `04_code_quality.md` | Оценка качества, технический долг, безопасность |
| `05_optimization_roadmap.md` | Дорожная карта улучшений и приоритеты |
| `06+` | Специфика проекта: Alembic, фронтенд, деплой, рендеринг Markdown и т.п. |

Отличия от этой схемы есть только в `AmiaBlog/` (свои имена файлов) — см. его `AGENTS.ru.md`.

## 4. Как работать с запросами пользователя

### 4.1. Определение проекта

1. Если вопрос касается конкретного проекта — работайте **только** с его папкой.
2. Если проект не назван — определите его по контексту (упоминание стека, функции,
   эндпоинта). Например: «ANSI-арт» → `luovkle.com`; «Redis-кэш пользователей» →
   `fastAPIuser-suren`; «MDUIv2» → `AmiaBlog`; «без ORM» → `diegolonio-dot-com`.
3. Если вопрос общий («как в моих проектах делается аутентификация») — сравните
   подходы по нескольким проектам, явно указывая, о каком проекте речь.

### 4.2. Порядок чтения информации по проекту

1. `AGENTS.md` / `AGENTS.ru.md` в папке проекта — правила и краткая сводка.
2. `README.md` / `README.ru.md` — назначение и быстрый старт.
3. Файлы `docs/` — по необходимости, начиная с `01_project_structure.md`.

### 4.3. Правила ответов

- **Язык ответов** — русский (вся документация на русском).
- Всегда указывайте, **к какому проекту** относится ответ.
- Отвечайте на основе документации; не предполагайте наличие кода — его здесь нет.
- Если документация не покрывает вопрос — честно скажите об этом и предложите,
  какую документацию стоит дополнить.
- При сравнении проектов используйте таблицу из раздела 2 как отправную точку.

### 4.4. Типовые сценарии

| Запрос пользователя | Что делать |
|---|---|
| «Как устроен проект X?» | Прочитать `X/README*` + `X/docs/01…02…` и пересказать |
| «Сравни проекты по Y» | Выбрать релевантные `docs/02_architecture.md` у нескольких проектов, дать сравнительную таблицу |
| «Где описан эндпоинт/роут Z?» | Искать в `docs/03_execution_flow.md` соответствующего проекта |
| «Напиши раздел документации в стиле остальных» | Ориентироваться на структуру и стиль `docs/` соседних проектов |
| «Составь план улучшений» | Опираться на `docs/05_optimization_roadmap.md` и `docs/04_code_quality.md` |

## 5. Что допустимо и что нет

**Допустимо:**
- читать любые файлы документации в воркспейсе;
- создавать/редактировать Markdown-файлы документации по запросу пользователя;
- предлагать изменения в структуру документации.

**Недопустимо:**
- предполагать, что исходный код проектов находится в этом воркспейсе;
- выдумывать факты о коде, которых нет в документации;
- смешивать контекст разных проектов без явного указания, о каком проекте речь.
