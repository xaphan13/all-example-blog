# Отчёт по фронтенду: luovkle.com

## Общая архитектура

**luovkle.com** — это уникальный монолитный персональный блог и портфолио, построенный на парадигме **Server-Side Rendering (SSR) без базы данных**. Весь контент хранится в файловой системе (в Markdown) и кэшируется в оперативной памяти бэкенда (FastAPI).

Ключевая фишка фронтенда в этом проекте — **Контентное согласование (Content Negotiation)**. Приложение отдаёт принципиально разный контент в зависимости от HTTP-заголовка `User-Agent`.

**Используемые технологии и библиотеки:**
- **Jinja2:** Шаблонизатор для HTML.
- **Tailwind CSS (сборка pnpm):** Стилизация.
- **BeautifulSoup:** Серверная обработка HTML.
- **Rich:** Библиотека для генерации ANSI (текстового) интерфейса в консоли.

---

## Как связаны между собой элементы

### 1. Двойной рендеринг (Браузер vs. Терминал)

На уровне бэкенда FastAPI проверяет заголовок клиента:
- Если клиент — браузер (Chrome, Firefox и т.д.), сервер рендерит `.jinja2` HTML шаблоны.
- Если клиент — консольная утилита (`curl`, `httpie`, `wget`), сервер применяет **ANSI шаблоны** (с помощью библиотеки Rich) и отдает `text/plain`.

**HTML поток (Браузер):**
Контент загружается из `index.md`, парсится библиотекой Python Markdown. Затем `BeautifulSoup` может изменять сгенерированный HTML, после чего он вставляется в Jinja2 шаблоны (`app/templates/`), стилизованные Tailwind CSS.
```jinja2
<!-- Типичный шаблон блога -->
<article class="prose prose-slate max-w-none">
    <h1>{{ post.title }}</h1>
    {{ post.content_html | safe }}
</article>
```

**ANSI поток (curl):**
Для `curl https://luovkle.com` сервер отдает сырой текст с escape-последовательностями, которые терминал раскрашивает:
```python
# Использование Rich для рендеринга консольного ответа
from rich.console import Console
from rich.markdown import Markdown
console = Console(force_terminal=True, force_jupyter=False)
console.print(Markdown(post.content_md))
# Вывод перехватывается и возвращается как PlainTextResponse
```
*Почему это сделано так:* Это гиковская фича, позволяющая программистам читать блог прямо в терминале, не открывая браузер, сохраняя при этом красивое форматирование и читабельность.

### 2. Управление стилями и сборка (Tailwind)
В отличие от других проектов в воркспейсе, luovkle.com **собирает Tailwind CSS локально**.
В проекте есть `package.json` и `pnpm-workspace.yaml`.

```json
// package.json
"scripts": {
    "build:css": "tailwindcss -i ./app/assets/input.css -o ./app/static/styles.css --minify",
    "watch:css": "tailwindcss -i ./app/assets/input.css -o ./app/static/styles.css --watch"
}
```
*Почему это сделано так:* Использование сборщика (вместо CDN) — это production-ready подход. Он удаляет неиспользуемые CSS классы (purge) и генерирует один минифицированный `styles.css`. Это уменьшает размер страницы, улучшает производительность загрузки (FCP) и убирает зависимость от внешнего CDN.

### 3. Оптимизация медиа (Изображения)
Фронтенд тесно связан с инфраструктурой CLI скриптов (`cli/`). Фотографии, добавленные в Markdown файлы автора, автоматически конвертируются в современные веб-форматы (WebP, AVIF) через команду `make images-optimize`. Шаблоны используют эти оптимизированные файлы для снижения нагрузки на канал.

Для консольной версии (`curl`), изображения прогоняются через скрипт `make images-ansi`, который генерирует **ANSI-арт** (картинки, нарисованные цветными символами), чтобы они отображались прямо в терминале.
